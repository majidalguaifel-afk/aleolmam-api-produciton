# نظام API — شركة الإلمام للخدمات اللوجستية

نظام خلفي (Backend) كامل لإدارة الشحنات، مصمم ليكون:
1. **واجهة API** تستخدمها جهات خارجية (تجار، منصات، شركات مثل "أوتو") لإنشاء
   طلبات شحن ومتابعتها.
2. **طبقة ربط موحّدة** توزّع هذه الطلبات إما على شركات شحن خارجية (أرامكس،
   سمسا، البريد السعودي) أو على **أسطول الإلمام الداخلي** (مناديبكم الخاصين).

---

## 🖥️ لوحة التحكم (بدون الحاجة لمبرمج)

افتح **`https://api.alelmam.com/admin`** — لوحة عربية سهلة تسوي منها كل شي بالضغط:

| الصفحة | وش تسوي فيها |
|---|---|
| **الرئيسية** | إحصائيات لحظية، تنبيهات (شحنات بانتظار مندوب، شحنات فاشلة)، وقائمة "خطوات البداية" |
| **الشحنات** | كل شحنات كل العملاء، بحث وفلاتر، تفاصيل وسجل تتبع، إنشاء طلب يدوي، إلغاء، **طباعة بوليصة بـ QR** |
| **التوزيع** | الشحنات بانتظار مندوب: تعيين بضغطة، وتحديث حالة التوصيل (استلام / في الطريق / تم التسليم / تعذّر) |
| **الخريطة** | تتبع حي لمواقع المناديب على خريطة OpenStreetMap المجانية بالكامل (بدون أي اشتراك) |
| **المناديب** | إضافة وإيقاف المناديب ومتابعة شحناتهم |
| **العملاء والربط** | إنشاء حساب لأي شركة (مثل أوتو) واستلام مفتاح الربط + **دليل ربط جاهز** بأمثلة كود (cURL / JavaScript / PHP / Python) تطبعه أو تنسخه |
| **شركات الشحن** | تفعيل/تعطيل، وإدخال بيانات أرامكس/سمسا/سبل (تُحفظ **مشفّرة**) |
| **الإعدادات** | تغيير كلمة المرور، فريق العمل والصلاحيات |

**أول مرة:** يظهر لك "أهلاً بك" لإنشاء حساب المدير الأول — لا يوجد كلمة مرور افتراضية.
النظام ينشئ الجداول لحاله عند التشغيل، فلا تحتاج أي أمر (`migrate` / `seed`).

**الأدوار:** مدير عام (كل شي) · مدير (عملاء وشركات وشحنات) · موظف تشغيل (متابعة وتوزيع الشحنات فقط).

## البنية التقنية

| الطبقة | التقنية المستخدمة |
|---|---|
| السيرفر | Node.js + Express |
| قاعدة البيانات | PostgreSQL (عبر Knex.js) |
| التخزين المؤقت | Redis |
| التوثيق | JWT (للوحة الإدارة) + مفاتيح API (للعملاء) |
| توثيق الواجهة | Swagger / OpenAPI 3 |

## هيكل المشروع

```
alelmam-api/
├── src/

│   ├── routes/           تعريف المسارات + توثيق Swagger المضمّن
│   └── docs/swagger.js   إعداد توثيق OpenAPI
├── public/admin/         🖥️ لوحة التحكم (واجهة عربية: HTML/CSS/JS بدون أي مكتبات خارجية)
├── migrations/           ترحيلات قاعدة البيانات (Knex) — تُطبَّق تلقائياً عند التشغيل
├── scripts/seed.js       تعبئة بيانات أولية (مدير، شركات شحن، عميل تجريبي)
├── postman/              مجموعة وبيئة Postman جاهزة للاستيراد
├── deploy/               إعدادات Nginx و PM2 للنشر على VPS
```

## التشغيل المحلي (للتجربة على جهازك قبل النشر)

### المتطلبات
- Node.js 18+ مثبت
- PostgreSQL مثبت وشغّال
- Redis مثبت وشغّال (اختياري — النظام يعمل بدونه لكن بدون تخزين مؤقت)

### الخطوات

```bash
npm install
cp .env.example .env
# افتح .env وعدّل DATABASE_URL و JWT_SECRET على الأقل

npm start           # الجداول وشركات الشحن تُنشأ تلقائياً — السيرفر على http://localhost:4000
```

ثم افتح `http://localhost:4000/admin` وأنشئ حساب المدير الأول.
(اختياري: `npm run seed` يضيف بيانات تجريبية: مدير `admin@alelmam.com` + عميل + مندوب.)

بعد التشغيل:
- **لوحة التحكم**: `http://localhost:4000/admin`
- **التوثيق التفاعلي (للمبرمجين)**: `http://localhost:4000/api-docs`
- **فحص الصحة**: `http://localhost:4000/health`

### استيراد Postman
افتح Postman → Import → اختر:
- `postman/Alelmam-API.postman_collection.json`
- `postman/Alelmam-API.postman_environment.json`

ثم فعّل بيئة "Al-Elmam API - Local" من القائمة أعلى يمين Postman، وابدأ بطلب
"تسجيل الدخول" أولاً (يعبّي التوكن تلقائياً للطلبات الباقية).

## السيناريوهان الأساسيان اللذان يدعمهما النظام

### السيناريو الأول: الإلمام ترسل شحنة لشركة خارجية
```
عميل API (تاجر) → POST /api/v1/shipments { carrierCode: "aramex", ... }
                 → النظام يستدعي AramexAdapter
                 → أرامكس توصّل الشحنة، وتُحدَّث الحالة عبر getTracking()
```

### السيناريو الثاني: شركة خارجية (مثل "أوتو") ترسل شحنة توصّلها الإلمام بنفسها
```
عميل API ("أوتو") → POST /api/v1/shipments { carrierCode: "internal", ... }
                   → تظهر في /api/v1/internal/shipments?unassigned=true
                   → فريق الإلمام يعيّن مندوباً: POST /internal/shipments/:id/assign
                   → المندوب يحدّث الحالة: POST /internal/shipments/:id/status
                   → "أوتو" تُشعَر تلقائياً عبر الويب هوك المسجّل لديها
```

## إضافة شركة شحن جديدة مستقبلاً

1. أنشئ `src/integrations/adapters/NewCarrierAdapter.js` ينفّذ نفس دوال
   `CarrierAdapter.js` (`createShipment`, `getTracking`, `cancelShipment`)
2. سجّلها في `src/integrations/carrierFactory.js` (سطر واحد)
3. أضف سجلاً لها في جدول `carriers` (عبر SQL مباشر أو سكربت seed)

**لا حاجة لتعديل أي كود آخر بالنظام** — هذا هو معنى "طبقة الربط المرنة".

## ملاحظات أمان مهمة

- **لا تشارك ملف `.env` مع أحد أبداً** — فيه كل الأسرار (كلمات مرور، مفاتيح)
- مفاتيح API تُعرض للعميل **مرة واحدة فقط** عند الإنشاء — النظام لا يخزّنها
  بنص صريح، فقط بصمة مشفّرة (hash) منها
- استخدم `openssl rand -hex 32` لتوليد `JWT_SECRET` قوي دائماً، ما تستخدم القيمة
  الافتراضية بملف `.env.example` أبداً في الإنتاج
